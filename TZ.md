# Техническое задание: Turbohub ETL

## 1. Цель продукта

Браузерное ETL-приложение для финансовых аналитиков и бухгалтеров управленческого учёта. Пользователь загружает Excel/CSV (или Google Таблицу), применяет одно или несколько правил трансформации и выгружает результат обратно в Excel — без сервера и без установки.

Продукт закрывает типовые операции консолидации: обогащение справочниками, аллокация, мэппинг статей, элиминация ВГО, свертка номенклатуры, РБП/начисления, матрица проводок Дт/Кт и управленческая переоценка.

## 2. Пользователи и границы

| Роль | Задачи |
| --- | --- |
| Финансовый аналитик | Собрать управленческий слой из нескольких выгрузок |
| Бухгалтер УУ | Проставить аналитики, Дт/Кт, отфильтровать ВГО |
| Методолог | Настроить каскад правил и выгрузить эталонный файл |

Вне скоупа этой версии: авторизация, сохранение сценариев в облаке, многопользовательский аудит, прямое подключение к 1С/ERP.

## 3. Пользовательский сценарий

1. Загрузить основную базу (файл, drag-and-drop или публичная ссылка Google Sheets).
2. Выбрать лист, увидеть предпросмотр строк и колонок.
3. Открыть библиотеку правил и настроить одно правило.
4. Применить правило. Результат показывается в таблице и доступен к выгрузке.
5. При включённой цепочке результат становится новой основной базой — следующее правило работает уже по нему.
6. При необходимости вернуть исходную загрузку кнопкой «Сбросить к исходной загрузке».

## 4. Функциональные требования

### 4.1. Загрузка данных

- Форматы: `.xlsx`, `.xls`, `.csv`.
- Несколько листов: выбирается лист; по умолчанию — первый непустой.
- Повторяющиеся заголовки колонок дедуплицируются (`Сумма`, `Сумма_2`).
- Drag-and-drop в зону загрузки.
- Загрузка по `http(s)`-ссылке; для Google Sheets — экспорт `/export?format=xlsx`. Если прямой запрос блокируется CORS, используются публичные прокси.
- Ошибки чтения файла и сети показываются текстом, без падения приложения.
- Библиотека Excel подключается как npm-пакет `xlsx` (без гонки с CDN).

### 4.2. Правило 1. Обогащение

- Режим «каскад правил»: если колонка содержит/равна/не равна/не содержит значение → записать тег в новую колонку. Первое сработавшее правило побеждает.
- Режим VLOOKUP: составной ключ из одной или нескольких пар колонок, индекс по справочнику O(n+m), берётся первое совпадение.
- Результат пишется в пользовательскую колонку.

### 4.3. Правило 2. Сплитование

- Строка источника 1 размножается по строкам базы распределения с совпадающим ключом.
- Сумма делится пропорционально драйверу; остаток округления кладётся на последнюю строку, чтобы сумма долей равнялась исходной.
- Одноимённые колонки базы не затирают поля основной строки: конфликт пишется в `{колонка}_база`.
- Если база не найдена или сумма драйверов = 0, исходная строка сохраняется со статусом.

### 4.4. Правило 3. Мэппинг

- Замена значений выбранной колонки по таблице соответствий.
- Таблицу можно заполнить вручную или загрузить из Excel (колонки «исходн*» / «эталон*» либо первые две).
- Несовпавшие значения помечаются «Без изменений».

### 4.5. Правило 4. Элиминация

- Набор условий с И/ИЛИ начиная со второго.
- Операторы: равно, не равно, содержит, не содержит.
- Мягкий режим: совпавшие строки остаются с `_Статус_Элиминации = Исключено`.
- Жёсткий режим: совпавшие строки удаляются из результата.

### 4.6. Правило 5. Агрегация

- Выбранные элементы сворачиваются в именованную группу.
- Сумма агрегируется; детализация сохраняется по выбранным измерениям (дата, ЦФО и т.д.).
- Строки, не входящие в группы, проходят без изменения.

### 4.7. Правило 6. Временные сдвиги

- Фильтр по нескольким условиям (И/ИЛИ).
- РБП: сумма явно выбранной колонки делится на N месяцев; остаток — на последний месяц.
- Сдвиг даты: значение выбранной колонки даты заменяется на указанную дату.

### 4.8. Правило 7. Проводки

- Загрузка плана счетов и базы операций.
- Матрица уникальных операций → счета Дт и Кт.
- Повторный выбор колонки операций не затирает уже заполненные Дт/Кт.
- В результат добавляются колонки `Дебет` и `Кредит`.

### 4.9. Правило 8. Переоценка

- Числовая колонка умножается на коэффициент.
- Парсер чисел понимает `1 234,56`, `1.234,56` и `1,234.56`.

### 4.10. Экспорт

- Файл `Turbohub_Result.xlsx`, лист `Результат_ETL`.
- На шаге результата — предпросмотр до 50 строк.

## 5. Нефункциональные требования

- Работа полностью в браузере, данные не уходят на собственный бэкенд (кроме выбранной пользователем ссылки/прокси).
- Трансформации вынесены в чистые функции и покрыты unit-тестами.
- UI на React + Tailwind, русский язык интерфейса.
- Сборки: `npm test`, `npm run build`.

## 6. Ошибки исходного однофайлового прототипа и статус

| # | Ошибка | Влияние | Исправление |
| --- | --- | --- | --- |
| 1 | Правила не образуют пайплайн: каждое применяется к исходной загрузке, а не к предыдущему результату | Нельзя последовательно обогатить → отфильтровать → переоценить | Цепочка включена по умолчанию; есть сброс к снимку первой загрузки |
| 2 | Текст «перетащите файл» без обработчиков drag-and-drop | Загрузка только через input | Реализован DnD |
| 3 | `xlsx` грузится с CDN без `onload`; гонка при быстрой загрузке файла | Ложные ошибки «библиотека ещё загружается» | Импорт npm-пакета |
| 4 | `elimAction` есть в логике, в UI нет переключателя soft/hard | Жёсткая элиминация недоступна | Добавлены режимы |
| 5 | В каскаде обогащения в коде есть «не равно», в селекте — нет | Оператор мёртвый | Добавлены «не равно» / «не содержит» |
| 6 | У VLOOKUP нельзя добавить второй ключ связи (в аллокации — можно) | Составной ключ недоступен | Кнопки «+ ключ» / удаление |
| 7 | Accrual: нельзя добавить второе условие, нет И/ИЛИ, сумма ищется по имени колонки | РБП ломается на колонке «Amount» | Мультиусловия, выбор колонки суммы |
| 8 | `Math.round(sum/n)` без остатка на последнем периоде | 100 ₽ / 3 мес. ≠ 100 ₽ | Остаток на последнюю долю, округление до копеек |
| 9 | `1.234,56` парсился как `1.23456` | Искажение сумм EU/RU | Определение десятичного разделителя по последнему символу `,`/`.` |
| 10 | VLOOKUP и аллокация — `find`/`filter` внутри цикла, O(n×m) | Зависание на больших справочниках | Индекс `Map` по составному ключу |
| 11 | Аллокация `{...r1, ...m}` затирает поля основной базы | Потеря аналитик источника 1 | Конфликт → колонка `*_база` |
| 12 | `useEffect` матрицы проводок сбрасывает введённые Дт/Кт | Пользователь теряет работу | Слияние по `opName` |
| 13 | Первый лист выбирался даже если он пустой | «Загружено 0 строк» при данных на втором листе | Первый непустой лист |
| 14 | Нет `FileReader.onerror` | Тихий провал чтения | Явная ошибка |
| 15 | Нет предпросмотра данных и результата | Невозможно проверить правило до Excel | Таблица preview |
| 16 | Общий объект `emptySource` как начальное состояние | Риск общей мутации | Фабрика `createEmptySource()` |
| 17 | Обновления массивов правил через замкнутое значение, а не `setPrev =>` | Потенциально потерянные клики | Функциональные апдейты |
| 18 | `activeTab` писался и не читался | Мёртвое состояние | Удалено |
| 19 | Пустые JSX-выражения `{}` на месте вырезанных комментариев | Шум в дереве React | Убраны |
| 20 | Нет тестов трансформаций | Регрессии не ловятся | Vitest по всем 8 правилам |

## 7. Критерии приёмки

- [x] Основная база загружается файлом и отображает preview.
- [x] Все 8 правил применяются без падения и дают предсказуемый Excel.
- [x] Цепочка правил изменяет рабочий набор; сброс возвращает исходник.
- [x] Суммы после сплитования и РБП сходятся с исходной в пределах копейки.
- [x] `npm test` и `npm run build` проходят.
